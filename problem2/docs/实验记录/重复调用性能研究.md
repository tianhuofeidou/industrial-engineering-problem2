# Gurobi重复调用性能研究

本次针对区间精确重排的调用开销进行研究。目标与编码不变：优化完整10工位的最终完成时间，工位6完成时间必须符合后段顺序；每轮的固定关系仍保留当前最好参考解。

## 分项计时

`build_model`记录创建环境、固定关系推导、时间界、变量与相邻弧约束、两两先后约束、初始解和模型写盘的用时，保存在`proof.build_timing`。Gurobi自己的`Runtime`另行记录。阶段累计时间还包括解提取、调度验证、CSV/SVG、模型和结果文件写入；不能用Runtime之和代替累计时间。

实际测得环境创建约1～3毫秒。仅复用环境不足以解释或解决主要开销。`--reuse-env`只共用许可证环境，每轮仍建立自己的模型，不表示复用模型、分支树或割平面。

## 相邻弧排除的计算

对工件`i`，用整数的二进制位记录已知后继集合；对工件`j`记录已知前驱集合。两者交集非空，表示有工件必须在`i`和`j`之间，不能直接选择相邻弧`i→j`。工位6还与已固定到当前机器的工件集合取交集，不能因另一台机器上的中间工件而排除弧。

实现把逐工件查询换成位集合交集，不改变排除规则。已对100组随机合法固定关系核对800次相邻弧计算，两个实现返回的弧、常数和最终推导完全相同；包括3、5、7和35工件。此项应用于公共筛选模块。

## 省略哪些约束

精简模型通过`--compact-model`显式开启，默认保持原模型。

设已固定`i`在`j`之前。原模型的反向时间约束为：

```text
S[i,k] >= C[j,k] - M
M = max(0, UB_C[j,k] - LB_S[i,k])
```

由`C[j,k] <= UB_C[j,k]`和`S[i,k] >= LB_S[i,k]`可知它必然成立，因此可以省略。正向约束`S[j,k] >= C[i,k]`保留；仅当`LB_S[j,k] >= UB_C[i,k]`也保证其成立时才省略。后段的工位6完工先后按相同方式处理。固定先后的反向位置不等式也由原位置界保证成立，省略它，但保留正向位置约束。自由先后关系的两向约束继续保留。

早期试验曾省去全部固定先后的时间约束，并收紧位置界。可行解范围与穷举最优值仍一致，但线性松弛变弱：六个Case 2范围累计8.19秒变成17.41秒。因此没有采用这版。另一版保留有效时间约束同时收紧位置界，累计8.48秒对8.40秒，收益不明显。最终精简选项保留原位置界，只删除变量上下界已保证成立的约束。

这些候选的源码快照、失败结果与日志均保留，不把减少约束数量视为整体加速证明。

## 对照方法与复核

`performance_main --mode replay`从已保存的逐轮限制读取相同编码、相同限制与相同求解预算；适合比较单次建模和求解成本。`--mode search`从同一参考编码分别完成自己的36轮区间搜索，适合比较累计时间和最终值。精简模型可能选择另一个同值最优编码，之后的区间与结果也可能改变，不能要求两条路线的轨迹相同。

`--legacy-baseline`使用本次备份中的旧弧筛选函数作对照，保留该文件的源码快照和哈希。其余模型与求解参数相同；新筛选实现可单独通过`environment`变体测试，`compact`变体额外启用精简约束。实验交替旧版和新版的运行次序，全部串行运行。

参考调度复用上一轮研究的结果；本次报告的秒数是追加精确阶段用时，不包括贪心和退火。两条路线使用相同起点以及空的样本分歧数据，因此不能直接与上一轮含样本引导的绝对结果比较。输入原文件只读，输出目录拒绝覆盖。完整结果见[实验记录](../../results/call_performance/实验记录.md)。

```powershell
python -B -m problem2.tests_research --integration --compact
python -B -m problem2.performance_main --mode replay --seeds 37 --variants baseline compact --legacy-baseline --output problem2/results/call_performance/replay_new
python -B -m problem2.performance_main --mode search --seeds 11 23 37 --variants baseline compact --legacy-baseline --output problem2/results/call_performance/search_new
python -B -m problem2.audit_research --output problem2/results/call_performance/search_new
```

精简选项的小实例验证仍检查全部10工位调度及工位6完成顺序。受限范围的OPTIMAL不能证明Case 2全局最优。
