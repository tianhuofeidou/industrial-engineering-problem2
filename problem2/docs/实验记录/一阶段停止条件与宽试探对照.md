# 一阶段停止条件与较宽完整编码试探

本次研究预算90分钟。新增独立实验入口、测试及本说明，默认一阶段、二阶段、编码时间递推和精确模型均保持不变。只建立Case 2受限模型，不建立完整模型；原始PDF、Excel只读。

## 停止条件四组对照

种子23进行三次独立初始化：每次从原始Excel完成8次构造、完整局部下降及默认2倍初温退火。该次新生成编码分别提供给四组，四组不互相提供改善编码或下界，旧10824不进入搜索。

|组合|精确阶段预算|轮数上限|
|---|---:|---:|
|s110_r80|110秒|80|
|s110_r200|110秒|200|
|s180_r80|180秒|80|
|s180_r200|180秒|200|

其他参数与当前区间策略相同：每轮Gurobi上限5秒，初始宽度5、自动调整，8线程、强化及紧凑模型、复用环境，范围缓存关闭。四组执行顺序随重复编号轮换。180秒/200轮的三个运行同时承担10824复现任务，不另外重复一套复现实验。

每组预算包括数据读取、建模、求解、验证、导出；记录实际用时、首次保存改善时间、逐轮模型与状态、终止原因。初始化及退火是同次比较的公共准备，单条从输入开始的算法成本仍需加上它。不能把轮数较少但用时未达上限的组说成相同实际计算预算。

秒数截断可能导致同一模型一个运行OPTIMAL、另一个中断，继而改变区间宽度及后续范围。报告将核对逐轮模型哈希及首次轨迹差异；四组设置对照不能自动消除这种执行波动，不凭一次差异断言独立参数的普遍作用。

## 三个新种子的较宽试探对照

新种子41、53、71均从原始输入重新构造及退火。同种子三方法共享新生成起点，各追加180秒，所有试探、建模、求解、验证导出计入；串行运行并轮换顺序。

|方法|规则|
|---|---|
|interval|区间策略，每轮5秒，最多200轮|
|probe32|每批随机抽24个未试探工件对，完整编码束搜索保留32个候选；整批结束接受其中严格最好解，继续试探|
|probe32_exact|相同抽样与试探规则；每批结束接受试探改善，再选择一个工件对，用受限Gurobi最多15秒继续改善|

束搜索在每次改变一个自由工件的A位置、B位置或机器后保留参考编码及31个最好的不同完整编码，并按相反工件次序重复。它评价完整35工件、10工位，不是对两工件的局部完工时间评分，也不是范围内所有编码的穷举。评分使用共享BatchEvaluator，返回最好候选再用逐个评分核对。

每批从同一个参考编码试探，批次中不混用不同参考的评分。整批找到改善时，接受最低完成时间的候选；精确方法随后放开该工件对。无严格改善时，按不同于参考的试探候选最低完成时间排序，再按完成时间不超过参考加50的候选数量排序，用独立随机数流打破并列。下界和gap不参加排序。这些量只用于选择，不解释为改善概率。

精确限制始终从精确调用前当前最好可行编码生成：两个选中工件可分别在A/B任意插入并换机器；其余工件固定机器和相对顺序，不固定位置或时间。保留参考方案，改善后不残留旧推论。限制范围仍约663个0/1变量，最优状态、下界和gap只对应本轮范围。

试探和精确方法的抽样随机流相同；精确改善后参考解不同，后续工件对不再保证相同，不宣称全程一一配对。每个参考编码与工件对只进入一次候选批次；参考编码改变后允许重新检查。该实验不把不变的两工件评分直接当作无改善证明。

## 运行与核验

```powershell
python -B -m unittest discover -s problem2/tests -t .
python -B -m problem2.tests.test_budget_probe --integration
python -B -m problem2.experiments.stage1_budget_probe --output problem2/results/stage1_budget_probe/run01 --global-seconds 4600
```

输出目录必须不存在。保存原始输入及准确源码快照SHA-256、完整350工序调度、每轮限制、模型、日志、状态、下界、gap、试探成本及改善来源。全局时间不足以完成下一组时保留部分结果，不冒称完成全部对照。

测试核对同一参考下不重复抽样、新参考重建固定条件、完整评分决定排序、候选有效及确定性。小实例以全编码穷举核对试探后受限模型最优值。结束后独立核验调度、约束、原始输入、代码快照和模型哈希，以及各比较组起点一致。

逐次报告各组最好值、第一次保存改善的时间及完整成本，不以平均值替代每次结果。求解器内部首次发现解的时刻与验证保存时刻分开；求解及预算检查可能有少量退出、导出开销，报告真实用时。仅对完成的受限范围报告证明，不证明原题全局最优。

## 已完成结果

|精确阶段设置|重复1|重复2|重复3|
|---|---:|---:|---:|
|110秒/80轮|10873|10873|10873|
|110秒/200轮|10873|10873|10873|
|180秒/80轮|10859|10859|10873|
|180秒/200轮|10824|10811|10825|

六组110秒运行都因时间用尽停止，实际70～76轮，80轮并未触发；三组180秒/80轮分别约131、132、120秒触发轮数上限，留下未使用时间。该样本支持同时提高两个上限。大设置三次都优于此前10847，但只有两次达到10824或以下，不保证输出同一目标或编码。

新的已验证最好可行值为10811。它在重复2的第116轮、追加171.73秒出现，加公共构造及退火约212.95秒。完整350工序与独立解码核验通过，仍没有全局最优证明。正式入口额外复跑同设置得到10824，完整用时约223.75秒。

各组追加上限180秒，种子53纯试探在检查完全部工件对后约152.79秒提前停止。纯试探在种子41更好，混合在种子71更好，没有一种新策略全面胜出。精确方法每批调用Gurobi，减少了试探数量；改善后参考编码及后续范围也会改变，不能将全部质量差异只归于调用时间。

本次90项回归测试与小实例穷举核验通过。默认参数和旧方案不替换，只提供新增实验入口及较大预算运行命令。逐次时刻、真实完整成本、模型轨迹差异、试探及求解开销见[实验记录](../../results/stage1_budget_probe/run01/实验记录.md)。
