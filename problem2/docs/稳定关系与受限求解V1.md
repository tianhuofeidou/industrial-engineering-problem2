# 启发式记录稳定关系并缩小Gurobi模型

本方案使用原题的一般模型与 `Chromosome(a,b,machines)`，目标仍是全部10工位的最终完成时间。启发式包括模拟退火、禁忌搜索和变邻域搜索，不使用遗传种群，不遍历所有工件组合。搜索结束后从记录中提取固定关系，最多求解3个受限模型。局部范围的最优性不能作为原题全局最优性证明。

## 1. 记录对象

前段A和后段B分别记录任意两工件的先后关系。A、B、6-1、6-2分别记录紧邻弧，虚拟起点和终点也参加记录，空队列用起点到终点的弧表示。机器归属按工件编号记录。工位6队列从b按机器归属筛选，机器翻转即使未改变b也可能改变两条队列的相邻弧。

全程稳定是初始关系在所有外层实际接受解中均成立，发生一次改变后即永久取消该标记。变邻域的外层解指扰动、完整局部下降后被接受的解；下降中的临时变化通过打破与恢复记录反映，不混同外层稳定性。试探、禁忌阻止和实际接受分别记录。

为控制开销，只对仍全程稳定的初始关系累计尝试信息；首次实际改变后停止累计这条关系的尝试统计。候选只为需要检查的队列建立位置表或相邻集合，满足的关系用整数中的位记录，缓存最多20000个编码。稳定集合只能减少，因此已有记录可以与当前集合取交集；全部初始关系改变后跳过试探关系检查。不同样本用集合去重，不逐一比较64个历史编码。不保存每次完整调度，不添加随机数调用。

## 2. 筛选规则

所有固定关系必须与当前最好可行编码一致。默认规则是初版可配置阈值，并非“属于全局最优”的概率估计：

| 方法 | 全程稳定关系的有效证据 |
| --- | --- |
| 模拟退火 | 至少20次允许打破的试探，其中至少5次温度不低于初温的10%；温度和候选目标差分别记录 |
| 禁忌搜索 | 至少20次不被禁忌阻止的打破试探；记录每步允许打破该关系的最好候选与当步选中候选的目标差，其累计差须为正 |
| 变邻域 | 至少10次扰动打破该关系；局部下降恢复比例至少80%；最终未恢复的候选若存在，其最好目标仍须比扰动前差 |

初温仍按既有正目标差校准，退火接受概率与随机数调用不变。禁忌阻止的候选不增加有效尝试计数。一次移动可能改变多条关系，目标差是整个候选编码的差，不能归因于某一条边。

另外保存最近最多64个不同编码，重复停留不增加支持次数。从中取目标不超过最终最好值1.03倍的最近最多24个编码，至少5个不同编码才允许提取后期一致关系。当前最好编码也参与交集。后期一致单独标注 `basis=late_samples`，不冒充全程不变；同一关系优先使用全程证据。

## 3. 直接缩小模型

`StableConstraints`将记录转成机器常量、先后常量和确定相邻弧。工位6的确定相邻弧同时确定两端真实工件的机器归属；A、B相邻弧蕴含先后关系，固定先后的传递关系也代入常量。

`exact_case1.build_model(...,stable_constraints=...)`与旧 `free_jobs` 接口互斥。固定的x、order与z直接作为整数常量，不能再选择的z为0；与确定前驱、后继、机器归属或先后关系冲突的相邻弧不建立变量。完整模型原有0/1变量数为 `5*n*n+5*n+2`，结果记录缩小前后的数量与Gurobi日志中的预处理结果。

每个工件的10工位开始和完成变量全部保留。连续组合不合并成加工时间相加的虚拟工件。仍按 `max(前驱完成,本工件到达)+setup` 的不等式约束非首件，队首无换模；B弧和先后关系必须符合工位6实际完成先后。时间上界和Big-M继续由参考可行调度H推导，不引入新的换模维度。

固定关系均保留参考可行解，因此可以设置其完整MIP start与 `Cmax<=H`。没有解时返回参考解，不把它冒充求解器输出；有解时独立检查，再按同编码解码为完整调度。原始求解器时间表另存 `solver_schedule/`。OPTIMAL时求解器目标与同编码解码目标必须一致。

## 4. 少量求解与解除固定

第一轮使用全部选中关系。找到改善时更新参考解，后续轮次继续保持现有关系；求完当前范围且无改善时，解除剩余直接关系的25%（向上取整，至少一条），后期一致先解除，全程证据再按有效尝试数排序。机器和先后的推论从剩余直接关系重新计算，不残留已解除关系的推论。

超时且没有改善时停止，不因难以求完而放开更多选择。最多3轮，每轮有独立TimeLimit；Case 2初版试跑每轮120秒。若没有支持固定的关系则跳过精确阶段，明确记录 `no_supported_fixed_relations`，不自动运行未缩小的完整Case 2模型。

这是一次启发式探索接少量受限模型的初版；尚未实现求解结果返回启发式继续搜索，也不是等总时间的性能对照。

## 5. 运行与输出

从项目根目录执行，使用已有openpyxl和gurobipy：

```powershell
python -B -m problem2.tests_stable
python -B -m problem2.tests_stable --integration
python -B -m problem2.stable_main --case 1 --seed 11 --measure-overhead --solver-seconds 30 --output problem2/results/stable_relations/case1_new
python -B -m problem2.stable_main --case 2 --methods annealing --seed 11 --measure-overhead --solver-seconds 120 --output problem2/results/stable_relations/case2_new
```

`--measure-overhead`额外运行相同初始化、种子和参数的未记录版本，检查最好编码、目标与终止规则一致，报告两种运行的搜索耗时。这次额外诊断运行不计入实际混合流程耗时；顺序运行仍可能受CPU状态变化影响。`--min-attempts`、`--min-perturbations`、`--min-late-samples`、`--release-fraction`可配置。Case 2默认只运行退火；旧Case 1和genetic_main入口范围不扩大。

输出目录存在时拒绝覆盖。保存原始输入及代码哈希、参数、初始化、完整调度JSON/CSV/SVG、搜索历史、全部关系证据、选中关系及其推论、每轮MPS/MIP start/解文件/日志、变量数、状态、范围下界、差距和耗时。日志下界及gap仅对应该轮受限模型。

小实例集成测试把不固定、混合固定、全部固定三种模型与288个编码穷举对照。单元测试检查温度、禁忌阻止、恢复、重复样本、相邻弧删除、参考解保留及记录不改变搜索结果。正式试跑结论另写实验记录，不能由缩小变量数直接推断运行加速。
