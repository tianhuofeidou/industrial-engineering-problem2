# 并行多起点搜索

针对一次初始化下降后只保留一个编码的问题，保留多个完成局部下降的编码，再分别搜索。编码、加工时间、换模公式和完整10工位目标值不变。工位6仍可为满足选定完工全序而主动等待。

## 初始化与筛选

默认分别使用种子11、23、37，每个种子完成8次贪心构造和原有的五邻域下降，也保留构造过程中最好编码下降后的结果。`initialize(..., retain_candidates=True)`只是额外导出候选，不改变原初始化的随机数调用、评分顺序和返回最好编码。未设置该参数时保持原行为。

去除完全相同的三数组编码。最低目标值的编码一定入选；其余在最低值的1.10倍以内选择。每次选择与已选起点最小差异最大的候选，同分时优先较小目标值。差异由前段排列的工件对先后不同数量、后段排列的工件对先后不同数量、机器归属不同数量组成，各除以可能的差异数后相加。不是仅比较排列位置；一个工件插入造成后续位置整体变化时不会误算所有工件都改变了先后关系。

筛选发生在下降之后；候选不足时减少实际进程数，记录实际数量，不复制同一编码。质量比例是搜索参数，不是题目约束，也不保证选出的起点能产生更好结果。

## 独立搜索与截止

默认四个独立Python进程，各自运行已有三工件联合重排、扰动与局部下降。求解器轮数设为0。每个进程拥有自己的当前编码、最好编码、完整范围记录和随机种子；进程间不交换编码。结束时统一比较已验证的完整调度并保留最低目标值。

1800秒从输入加载前开始计算，包含源码快照、初始化、起点筛选、启动进程和搜索。所有进程收到同一个绝对截止时间。既有搜索在候选批次或阶段之间检查截止，单批计算及最终验证、导出可能造成少量超时，报告实际总时间。截止一分钟后仍未退出的异常进程会被终止；其已经保存且重新验证通过的检查点可作为结果，状态不会伪装成正常完成。

四进程的30分钟与单进程30分钟墙钟时间相近，但使用更多CPU计算量；报告每个进程CPU时间与墙钟时间之和。一次成功运行也不能证明所有随机种子都更好，更不能证明原题全局最优。

## 运行与验证

```powershell
D:/python3.14/python.exe -B -m unittest problem2.tests_multistart problem2.tests_joint problem2.tests_batch problem2.tests_four_methods
D:/python3.14/python.exe -B -m problem2.multistart_main --case 2 --seconds 1800 --workers 4 --output problem2/results/multistart_30min/run01
```

输出目录必须不存在。保存输入与源码SHA-256、源码快照、全部候选与起点差异、各进程日志/事件/完整调度/改进记录、合并后的下降过程和最终完整调度。每个候选始终含全部工件；最终结果使用独立一般模型验证器检查350道工序、到达后换模、机器排队、工位6完工次序和后段一致顺序。
