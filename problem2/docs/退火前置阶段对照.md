# 退火前置阶段对照

## 问题与方案

比较贪心构造加完整局部下降后直接进入Gurobi，和先模拟退火再进入Gurobi两种流程。目的不是比较退火最终值本身，而是判断前置退火是否帮助后续精确改善。

Case 2使用种子23、53、71，从原始Excel重新做8次构造和完整局部下降。同种子两组共用该次初始编码，不读取历史调度或最好值。初始化成本单独记录，并计入每组独立运行总成本。

两组从初始化完成后的同一编码开始，各用180秒追加预算。计时包含数据读取、加载初始方案、退火（如有）、建模、Gurobi求解、验证和导出。退火组使用当前温度倍率2、降温0.97、每温度1000次操作及原终温规则，允许正常完成，但它的全部耗时从180秒中扣除；直接组将剩余预算全部用于Gurobi。

Gurobi固定区间宽度5，每轮最多5秒、8线程，轮数上限5000，关闭宽度自适应及范围缓存，开启现有模型强化和紧凑约束，共用进程内环境。三个种子串行，两方法执行顺序轮换，分别记录逐轮限制、模型哈希、结果和完整调度。窗口和约束都从该组当前最好编码生成，不共享另一组的新解。

## 解释范围

本对照只验证固定宽度5、180秒追加预算下的表现。固定宽度7、9和长预算可能有不同结果，不据此直接认定退火普遍无用。时间截断及多线程会改变停止位置，同种子只各运行一次时不能把每次差异当作稳定保证。当前正式默认算法不改。

每轮OPTIMAL只证明本轮受限范围最优，搜索结束的最好值是可行解，不能视为Case 2全局最优或已完整检查所有区间。

## 文件与运行

- `experiments/annealing_ablation.py`组织实验、共用现有退火和区间求解函数。
- `tests/test_annealing_ablation.py`核对退火时间扣减、直接组不退火及起点一致。
- `results/annealing_ablation/`保存独立输出，不覆盖早期结果。

```text
python -B -m problem2.experiments.annealing_ablation --output problem2/results/annealing_ablation/run_new
python -B -m unittest discover -s problem2/tests -t .
```

完成后独立核验所有调度、输入和源码快照哈希、模型哈希、固定关系以及同种子两组起点和预算一致。逐次汇报最终值、首次达到最好值的时间、退火时间、Gurobi时间与轮数，不用平均值代替三个种子的结果。
