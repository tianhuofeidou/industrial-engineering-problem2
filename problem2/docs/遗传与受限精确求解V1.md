# 题目2遗传算法与受限精确求解初版

本文记录保留的时间预算初版。最新Case 1四算法共同初始化、固定终止规则和不限时商业求解器轮换见 [四算法对照设计](Case1四算法对照.md)，两种入口参数及历史记录分开保存。

## 1. 目标与范围

主方案为贪心构造初始种群 → 遗传搜索并保留优秀个体 → 选择可调整工件并生成固定约束 → 精确求解。随机化贪心单独运行仅是对照，遗传中间结果与精确结果来自同一次三段流程。主命令选择`--method hybrid`。

目标是最小化工位10的最晚完成时间，并生成完整可复核调度。原始PDF、Excel只读。Case 1运行随机化贪心、遗传及遗传加受限Gurobi；Case 2只运行启发式，入口和受限求解函数均禁止对Case 2启动商业求解器。

借鉴桌面ane-poc-algo的“启发式输出约束数据，数学模型加入这些约束，再由求解器优化”的流程。本题的附加约束是工件相对顺序和机器归属；物流模型的货量下界不直接迁移。此前5031秒全局最优证据仅用于算法返回后的评价，不参与初始化、停止条件、工件选择或时间上界。

## 2. 编码与统一解码

`Chromosome(a,b,machines)`是不可变三数组对象，工件编号在代码内从0开始。a为工位1～5的共同排列，b为工位6完工全序，machines按工件编号保存0/1归属，分别表示6-1、6-2。a、b各包含每个工件一次，机器分配长度为n。

前段按a递推；工位6和后段按b遍历。每条机器队列由b筛选归属得到。非首件最早加工开始时间为 `max(机器前件完成时间, 工件到达时间)+setup[前件,后件]`；首件换模为0。工位6的完成时间还取该最早完成时间与b中前一工件完成时间的最大值，必要时延后开工，以实现b；同时完成按b记录全序。工位7～10沿用实际完工全序b。

`encoding._calculate`是唯一时间递推实现。`evaluate`只计算最终完成时间，保留长度n的完成时间数组；`decode`记录n×10开始、完成时间并生成完整工序。每个工位各遍历工件一次，评分时间O(10n)、工作数组空间O(n)；完整解码空间O(10n)。独立验证仍由`exact_validation.py`完成，不调用递推函数。

旧完整精确入口的`decode(data,a,b,machines)`保留调用格式，转交统一解码模块。旧启发式采用队列各自最早开工的附加限制，其模块和结果保留；新搜索采用允许工位6等待的三数组编码。

## 3. 贪心构造与对照

初始顺序按各工件加工时间总和降序，机器先按工位6预计负载分配。前段逐件尝试全部插入位置，每个位置都评价完整编码，尚未插回的工件放尾部。前段完成后，再逐件插入b，同时尝试两台机器。首个构造确定地选择最小评分，后续构造随机打乱输入顺序，并以0.25概率从前三个候选中选择，增加方案差异。

随机化贪心对照在预算内重复构造，保存所有实际评价过的完整编码中的最好值。它不调用遗传操作和局部搜索。所有候选均使用全生产线Cmax，未插回工件不从目标中删除。

## 4. 遗传搜索

默认种群60、每种子10秒，预算包含初始化。种群由最多8个贪心构造、随机编码及最好编码的扰动组成。初始预算不足时仍返回已评价的完整可行编码。可指定代数上限，代数与时间先达到者停止；固定代数在充足时间预算下可复现，按时间停止不保证跨运行一致。

父代用三元锦标赛选择。a、b分别进行顺序交叉：保留一个亲本的区间，再按另一亲本的循环顺序填入未出现工件；机器数组按工件编号均匀交叉。两个排列各以0.35概率做一次交换或插入；机器数组以0.35概率翻转一个工件归属。编码合法性由这些操作保持。

每代保留约10%的精英，并加入约10%的随机个体。每10代再将一个随机个体替换为新的随机化贪心构造，避免完全随机个体分数较差而持续被淘汰。重复子代先跳过，尝试次数较多时允许重复，避免有限编码空间导致无法填满种群。每代对最好新个体抽样至多80个交换、插入、机器翻转候选，选其中最好值。因此当前实现是贪心、遗传结合局部搜索，不能把它与随机化贪心的差异全部归因于交叉操作。

评分缓存最多20000个编码，达到上限后清空；记录实际递推次数与缓存命中次数。历史最好编码独立保留。每代从历史保留个体与当前较好个体中更新最多12个不同编码：最好个体必留，在评分不超过最好值1.05倍的编码中，优先保留数组差异较大的方案。差异是两个排列对应位置及按工件编号的机器分配不相同的总项数。保留个体可能少于12个。

## 5. 从种群生成顺序约束

以历史最好编码作为唯一参考。对保留的优秀个体，分别比较前段、后段任意两工件的先后关系；每个不一致的关系给涉及的两个工件各加1分。机器归属不一致给对应工件加n−1分。按总差异降序选默认3个工件放开；分数相同时按工件编号决定，不把逐对多数意见直接固定。

对未选中工件：

- 机器归属保持参考方案，设置相应x变量；
- 在A、B中保留它们之间所有两两先后关系，设置已有`order_A`、`order_B`变量；
- 不固定具体位置，不要求它们紧邻，不固定开始或完成时间。

选中工件的前段插入位置、完工排序、机器归属由求解器选择，两个选中工件之间也自由重排。所有固定关系来自同一个可行参考编码，因此不会由多数表决形成循环，参考方案仍满足受限模型。

例如n=7、放开3个工件时，固定4个工件的机器归属，以及A、B各6条先后关系，共16条附加等式。原始相邻弧和时间变量仍存在，模型预处理可据固定关系进一步简化；初版并不声称所有变量数量都会直接下降。

## 6. 受限精确模型

复用`exact_case1.build_model(...,free_jobs=...)`，其默认`None`仍是原题完整模型。原题换模、到达、队列、工位6实际完工排序和Big-M约束不变。使用遗传最好调度作为MIP start，并以其完整完成时间H作为可行上界；没有读取5031设置H。

初版受限优化仅使用Gurobi。默认最多10秒、8线程，相对和绝对gap阈值0。求解器无可用解时保留已验证参考方案，并记录fallback来源；不是把参考方案冒充求解器输出。许可证或建模错误向上传播，不静默吞掉。

`scope=restricted`时，求解器OPTIMAL仅证明当前限制下最优；记录`bound`、`gap`，不将其作为原题全局下界。只有全部工件放开时模型范围才恢复原题。与已有全局基准相同是另一条事后判断，单独记录`benchmark_comparison`，同时核对原始输入哈希。

## 7. 运行与输出

在项目根目录运行，使用新输出目录：

```powershell
python -B -m problem2.tests_genetic
python -B -m problem2.tests_genetic --integration
python -B -m problem2.genetic_main --case 1 --method hybrid --seconds 10 --seeds 11 23 37 --free-jobs 3 --solver-seconds 10 --output problem2/results/three_stage_new
python -B -m problem2.genetic_main --case 1 --method compare --seconds 10 --seeds 11 23 37 --free-jobs 3 --solver-seconds 10 --output problem2/results/compare_new
python -B -m problem2.genetic_main --case 2 --method genetic --seconds 10 --seeds 11 23 37 --output problem2/results/case2_genetic_new
```

`--method greedy/genetic`仅运行对应启发式，`hybrid`运行遗传及受限优化，`compare`额外运行随机化贪心。hybrid和compare仅允许`--case 1`；`--case all`只能配greedy或genetic。`--generations`、`--population`、`--archive-size`、`--mutation-rate`、`--local-candidates`、`--free-jobs`和求解预算均可配置。受限模型使用正常登录用户许可证。

每个种子分别保存greedy、genetic、hybrid目录，包含完整JSON、CSV、SVG甘特图。遗传结果另存历史和优秀个体；受限求解另存`restrictions.json`、MPS、初始解、解文件和日志。总目录保存`summary.json`、`runs.csv`和参数。入口拒绝覆盖输出根目录。

`compare`中的纯遗传与混合结果使用同一次遗传搜索，便于观察求解器增益；不是两次独立遗传运行。随机化贪心与遗传拥有相同启发式时间预算，混合方法另有求解预算，所以报告搜索加精确优化总时间，不将三种结果当作相同总预算的公平对照。输入、导出和验证耗时另由每种子墙钟记录说明。

## 8. 验证与初版限制

测试覆盖评分与完整解码一致、全部3工件288个编码可行性、遗传操作保持工件完整且不修改亲本、固定相对顺序仍允许插入、全固定时只有参考编码、保留个体的质量与差异、固定代数可复现、极短预算返回完整编码、Case 2禁止受限求解及35工件SVG导出。受限集成测试将固定0个可调整工件和放开1个工件的MILP最优值分别与对应候选穷举比较。

初版只有一次受限优化；尚未实现连续扩大范围、把精确结果反馈给下一轮遗传或正式参数调优。实际实验结果单独记录，算法规范不承诺遗传优于随机化贪心，也不承诺每个受限范围都包含全局最优方案。
