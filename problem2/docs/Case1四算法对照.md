# Case 1四种搜索与商业求解器对照

## 1. 目标、编码与共同初始化

只处理题目2 Case 1的7工件；Case 2不运行。原始PDF、Excel和旧结果不变。编码仍为 `Chromosome(a,b,machines)`，评分与完整解码统一由encoding.py实现。目标是完整10工位的最终完成时间。

每个种子先进行8次贪心构造，每个返回编码完成局部下降；贪心过程中实际评价过的最好完整编码也完成下降。局部下降完整检查前段插入、后段插入、机器翻转、前段交换、后段交换。某个邻域发现严格改善后接受最好候选，并回到第一个邻域；完整一轮无改善才结束。局部最优只相对于这五种操作，不是全局证明。

四种搜索接收完全相同的初始编码，分别使用种子11、23、37、53、71。遗传种群的其余成员由随机编码及该解扰动构造，评价和种群构造计入遗传阶段耗时。初始化单独计时，作为每种方法总耗时的一部分；实际实验只计算一次并共享，不将真实墙钟重复相加。

## 2. 四种方法与终止条件

| 方法 | 搜索过程 | 终止规则 |
| --- | --- | --- |
| 变邻域搜索VNS | 对当前解依次扰动2、3、4个不同工件，调整排列和机器归属，再完整局部下降；严格改善则接受并回到强度2 | 每档连续50次无改善，全部三档耗尽 |
| 禁忌搜索TS | 完整评价133个具体操作，选允许的最好候选，可接受较差值；禁止短期恢复最近修改的两两顺序或机器归属 | 连续5000步未改善历史最好 |
| 模拟退火SA | 从133个具体操作等概率抽取，改善及等值移动接受，变差量Δ以exp(-Δ/T)概率接受 | 每温度1000步，T乘0.95，降到初温万分之一以下 |
| 遗传搜索GA | 种群60；两排列顺序交叉、按工件编号交叉机器、交换/插入/机器变异、精英保留、随机个体、定期贪心补入及抽样局部搜索 | 固定5000代，不因停滞或已知5031提前停止 |

TS期限每次取3～7步，恢复旧属性受禁忌限制；若改善扫描开始时的历史最好值，则允许破例。所有候选均禁忌时，取最早解除禁忌的移动，记录次数。顺序属性按工件对定义，不按易变的位置定义。

SA先抽取至多64个初始邻居，用正变差量的中位数除以−log(0.8)设初温，若没有正变差量则取1。校准计入SA的耗时与评价次数。使用温度比例而非绝对目标值；不读取已知最优值。

所有方法独立保存历史最好编码。GA包括抽样局部搜索，不能把其全部收益归因于交叉；VNS包含完整局部下降，TS与SA按其规定逐步移动。比较的是这四个明确实现，不是抽象算法名称。

启发式不设秒数上限。时间取实际完成终止规则的耗时；不同方法评价次数和总时间不同，不能宣称这是相同时间预算的公平对照。额外报告质量与时间，后续若要比较固定计算预算，需要独立实验。

## 3. 商业求解器阶段

每种启发式结束后，以最好解作为参考，对7工件的全部35个三工件组合依次运行Gurobi。每个范围允许所选工件重新插入前后段及改变机器，其他工件仅固定相对顺序和机器归属，位置与时间不固定。原题时间变量、不提前换模、实际完工排序、首件和取整规则不变。

模型使用参考解作可行上界及MIP start，不固定它的时间。每个模型不设置TimeLimit，MIPGap与MIPGapAbs均为0，8线程。只有OPTIMAL、调度独立验证通过且评分与模型目标一致，才认为这个范围完成。

某范围改善时更新参考编码，继续检查本轮剩余组合。本轮存在改善则重新检查全部35个组合；只有完整一轮在同一参考解上全部无改善，才终止。各范围保留MPS、初始解、解文件、日志、完整调度与状态；rotation.json每完成一个范围更新，便于中断后核查现场。初版每个范围重新建模，建模、文件及求解总成本均如实记录，尚未复用模型。

终止证明的是：保持其余工件相对顺序和机器归属时，任意三工件范围都不能进一步降低目标；这是局部最优，不是原题全局证明。scope仍为restricted。无时限模型若因许可证、数值或其他原因没有OPTIMAL则报错并保留现场，不假装完成。

## 4. 输出、运行与评价

正式计时依次运行，减少CPU争用。运行前保存参数与输入、代码哈希；全部搜索和求解结束后才读取已有5031基准，比较命中次数及差距，不用于任何搜索判断。

```powershell
python -B -m problem2.tests_four_methods
python -B -m problem2.compare_case1 --output problem2/results/case1_four_methods/run_new
```

默认采用上述已确认参数及5个种子。支持 --methods vns tabu annealing genetic、--seeds、--generations、--population、--vns-failures、--tabu-stall、--sa-moves、--threads。没有Case 2入口。--skip-exact仅用于检查启发式，不作为正式三段流程。输出目录存在时拒绝覆盖。

每个种子保存共同initial目录；每种方法保存heuristic、exact及status.json。heuristic包括完整JSON/CSV/SVG、评分历史、算法终止参数、优秀个体；exact包括逐范围和final调度。根目录保存config.json、summary.json、runs.csv。summary.json在运行过程中标明complete=false，只有所有阶段完成才标true。

报告分开列出贪心阶段、初始化下降、搜索结束和精确结束的目标，最优命中次数、均值与标准差、初始化/搜索/精确及总时间、实际评分和缓存次数。若初始化达到5031，后续命中不能算作该算法的目标值改善。计时可能受到机器负载影响，固定迭代规则和种子用于复现具体搜索过程。
