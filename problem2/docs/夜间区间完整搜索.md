# 夜间区间完整搜索

三个种子23、53、71，固定宽度3、5、7、9，各宽度一个独立进程，每个Gurobi模型4线程。各进程内顺序处理三个种子。普通一阶段入口及默认参数不变。

## 起点与独立性

沿用已核验的`stage1_width_comparison/run02`三个退火起点，分别10952、11060、11086。同一个种子的四个宽度从相同编码出发，不使用其他宽度的新解，也不使用历史最好结果辅助搜索。该次初始化和退火计算成本另行记录，不计入夜间追加时间。启动时核对原始输入和全部源码哈希，保存独立快照及完整起点调度。

## 求解与停止

每个范围使用同一参考编码生成固定关系：区间内可重排，其他相对顺序固定，区间工件并集可换机器，其余机器归属固定。工序时间仍为一般模型的不等式，允许工位6等待，后段顺序与完工时间一致。

不设置单轮TimeLimit、总时间上限或轮数上限。每轮必须为OPTIMAL，受限目标与下界在容差内一致且独立调度验证通过，才进入下一轮。异常、内存停止或未完成证明不能作为该范围无改善，记录失败并保留检查点。

严格改善才更新参考编码并重新检查全部区间。同一参考编码的区间组合不重复求解，只有当前编码的全部`(35-w+1)^2`对区间均证明无严格改善，才结束该种子。证明是该宽度区间邻域的局部最优，不是Case 2全局最优，也不是全部工件自由重排的最优。

共用每个进程的Gurobi环境，各轮重新建模。树节点达到约1GB时允许写入当前模型目录以减少树的内存占用；四进程竞争资源，单轮耗时不能与独占电脑的8线程实验直接比较。

## 输出、检查点与恢复

入口`python -B -m problem2.experiments.overnight_windows`，`--phase prepare --output 新目录`保存起点与配置；随后分别以`--phase worker --output 同一目录 --width 3/5/7/9`运行。

每个宽度保存`status.json`、每个种子的`checkpoint.json`、`rounds.jsonl`、最好完整调度，以及每轮限制、MPS、原生日志、解和验证结果。检查点用原子替换写入，保存当前编码、已证明范围、待求范围和随机数状态。运行中的模型进度可从其`solver.log`读取；检查点的最好值只表示已经求完并验证接受的结果。

同一宽度使用文件锁避免重复启动。进程关闭后，在输入和源码哈希保持一致时重新运行同一worker可读取检查点；已保存的最优模型结果核验后可复用，未完成的模型重新建立，搜索树不跨进程保存。失败轮次和文件保留，不覆盖旧目录。

Windows启动使用隐藏后台进程，输出重定向到各宽度日志；根目录`launcher.json`记录PID。全部四组启动验证后停止人工检查，由用户早上叫回后读取进度；不创建定时监控。
