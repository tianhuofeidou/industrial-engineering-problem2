# 一阶段短时限检查与追加求解对照

本次获批范围为一小时研究。新增受限模型会话、独立实验入口、测试及本说明，默认一阶段、二阶段和通用时间递推不修改，不建立Case 2完整模型。

## 假设与对照

此前单轮5秒可能尚未完成根节点处理；统一15秒能改善个别范围，却可能推迟检查到其他有用工件组合。本次检验先检查更多范围、再向少数范围追加时间是否划算。

三个种子11、23、37均从原始Excel重新进行8次构造、完整局部下降和默认2倍初温退火。同种子四方法从同一新生成编码开始，各追加180秒；读取、试探、建模、求解、验证与导出都计入。方法串行执行，按种子轮换次序。

|方法|每个范围首次求解|追加选择|
|---|---|---|
|interval|现有区间规则，5秒|现有宽度调整，最多200轮|
|fixed15|均匀随机选两个未尝试工件，15秒|不追加|
|adaptive_random|每批均匀抽四个范围，各5秒|未证明范围随机选一个，在原模型上追加10秒|
|adaptive_scored|与上一组相同的抽样规则，各5秒|对未证明范围做完整解码试探，按所得评分选一个追加10秒|

随机选范围和选择追加范围使用独立随机数流。两种追加方案在参考编码相同且已检查批次相同的情况下抽样一致，但改善导致后续参考编码和范围不同，因此不宣称全过程范围逐个相同。

两个自由工件可在前后段分别任意插入、选择机器；其余33个工件只固定机器和相对顺序，不固定位置及工序时间。所有固定值取自同一个当前最好可行编码。新参考编码出现时关闭旧待追加模型，下批重新生成限制。未证明的范围不说成没有改善空间；已证明的同一范围不继续求解，每个参考编码与工件对只新建一次模型。

## 继续求解与时间统计

`common/restricted_session.py`只调用共享`solver.build_model`、`solver.extract`、编码及独立验证器，不复制调度递推。停止后模型留在内存中；追加时不修改变量、约束、初始解或线程，不执行reset。不同范围分别保留模型，批次结束关闭。

采用每次调用的墙钟截止回调，记录实际耗时和`INTERRUPTED`状态；不是以`TIME_LIMIT`状态判定追加是否结束。记录每次Runtime、节点数、可行值、受限下界和gap，以及每次与累计墙钟耗时，避免不同Gurobi版本的累计日志与单次属性混淆。求解器停止检查及导出仍有少量开销，报告真实用时。

[Gurobi官方说明](https://support.gurobi.com/hc/en-us/community/posts/360077659972-Is-the-branch-and-bound-tree-saved-for-future-re-optimization)指出，不改变模型而继续求解时会保留搜索信息。本机先核查`Continuing optimization...`日志和模型哈希；无法核验则不进行正式实验。诊断重用历史参考编码，不含其历史构造成本，也不反馈正式搜索。

## 完整编码试探

对每个范围的两个工件依次改变A位置、B位置和机器，再按相反工件次序重复。每次位置检查全部35个位置，机器检查两种归属。束搜索每步保留参考编码及三个评分最好的不同完整编码；它只保留少量候选继续展开，不是穷举整个受限范围。

全部候选保留35个工件、两个完整排列和按编号的机器数组，使用共享`BatchEvaluator`评价完整10工位，并核对最终最好候选与逐个评分一致。若试探本身找到严格改善，直接保存，并关闭旧待追加模型。

没有改善时，以不同于参考编码的试探候选的最低完成时间排序；同值时优先试探中完成时间不超过参考值加50的候选较多的范围，再用独立随机流打破并列。这两个量只用来排序，不解释为改善概率或独立贡献。已证明范围不参加试探或追加，受限下界和gap不用于排序。

## 运行与证据

```powershell
python -B -m unittest discover -s problem2/tests -t .
python -B -m problem2.tests.test_adaptive_time --integration
python -B -m problem2.experiments.stage1_adaptive_time --output problem2/results/stage1_adaptive_time/run01 --global-seconds 2800
```

输出目录必须不存在。保存输入及源码SHA-256、模型、MIP初始解、每次中断与追加证明记录、完整调度、求解器可行值事件及改善来源。全局预算不足以完成下一个分支时保留部分记录，不冒称完成对照。报告每次最终值、首次改善时间、全部改善过程、范围数、追加数和试探开销，不以平均值替代逐次结果。

测试核查完整候选、固定约束、批量与逐个评分一致、已证明范围不再追加、下界不影响挑选、截止后返回可行编码。小实例全编码穷举对照受限模型最优值，并验证同模型中断后继续求解。正式结果独立核验调度与约束、原始输入和代码快照及模型哈希。所有OPTIMAL及下界只针对本轮限制范围，不是原题全局证明。

## 已完成结果

|种子|区间5秒|固定15秒|短跑后随机追加|短跑后按评分追加|
|---:|---:|---:|---:|---:|
|11|11052|11052|11052|11052|
|23|10824|10952|10952|10952|
|37|10932|10932|10932|10932|

各组均追加约180秒，三个种子的公共准备分别41.34、41.33、43.64秒（准确值见summary.json）。区间策略第95轮达到10834，第96轮达到10824；首次验证保存10824在追加173.35秒，加公共准备约214.68秒。完整350工序及重新解码通过；这刷新此前已知10847，但没有全局最优证明。区间预算110增至180秒、轮数80增至200同时改变，本轮不单独区分两者贡献。默认入口仍保持原值。

两种追加方案没有超过现有区间方案。本轮发现宽度4的束搜索有漏检：同一个已知可改善范围，保留4/8/16个候选均停在10952，保留32/64个候选能直接试探得到10945。事后宽度32在种子11全部595个工件对中找到11025，耗时161.28秒，未调用Gurobi；种子23仅检查54对即按研究截止时间停止，该部分不能当作完整对照。

同模型三次诊断中，连续15秒的两种停止接口都找到10945并完成受限证明；5+10秒也找到10945，但未在预算内完成证明。保留搜索状态不保证与连续运行表现相同。这是特定范围的诊断，不推广为所有模型的结论。

86项测试及小实例穷举核验通过。含事后诊断最终验证1321份调度、515个模型、34个同模型追加，全部输入/源码/模型哈希及固定条件通过。暂不采用新追加策略，保留区间策略，优先验证较大轮数及较宽解码试探。详见[逐次实验记录](../results/stage1_adaptive_time/run01/实验记录.md)。
