# 题目2 Case 1 精确模型

原始事实来源为项目根目录的 `问题2.pdf`、`问题2数据.xlsx`。本模型求解7工件算例，不处理另一个题目的 `问题1.pdf`。目标为最小化全部工件在工位10的最晚完成时间，系统首件在工位1从0开始。单位为秒。

## 1. 与旧方案的区别

旧启发式给定前段排列和工位6两条队列后，所有工位按最早可行时刻开工。原题没有规定必须最早开工，因此精确模型使用开始时间不等式，允许额外等待。工位6的等待会改变实际完工顺序，继而改变工位7～10的排列和相邻换模时间。

项目规范中原有“两层确定后时间表唯一确定”的表述，与原题允许推迟开工不一致；按用户确认的一般模型修正。旧代码及原始实验记录保留，不能用旧验证器要求一般模型的开始时间等于最早下界。

## 2. 变量

- `S[j,k]`、`C[j,k]`：工件j在工位k的加工开始、完成时间，连续非负变量。
- `x[j,m]`：工位6的机器归属，二元变量，两个机器的归属之和为1。
- `z[q,i,j]`：队列q中i紧邻j，二元变量。q为A、B、6-1、6-2；A是工位1～5的共同排列，B是工位7～10的共同排列。
- 虚拟起点、终点：表示每条队列的首件、末件；两条工位6队列可以为空，A、B必须包含全部工件。
- `pos[q,j]`：A或B中的位置，取值0到n−1的连续变量；两两先后变量辅助强化排列约束。
- `Cmax`：最终完成时间，满足 `Cmax >= C[j,10]`，目标最小化Cmax。

## 3. 队列与时间约束

A、B各工件入度、出度均为1，起点出度、终点入度各为1。工位6队列每个工件的入度、出度等于该机器的归属变量；允许起点直接连接终点表示空队列。

加工完成时间为开始时间加加工时长。工位6-1使用表2 M6；6-2使用 `(12*p+5)//10`。换模矩阵来自表4，有方向，所有机器共用同一矩阵；实际队列不会查询对角元。

每道非首工位满足 `S[j,k] >= C[j,k-1]`。当相邻弧i→j被选中时：

```text
S[j,k] >= C[i,k] + setup[i,j]
S[j,k] >= C[j,k-1] + setup[i,j]  （k > 1）
```

两者合起来为 `S[j,k] >= max(C[i,k], arrival[j,k]) + setup[i,j]`。换模不能提前到工件到达前。队首没有换模；每条工位6队列的队首分别免换模。A首件在工位1的开始时间固定为0。

时间约束与严格正加工时长排除队列环：沿一个环把约束相加会得到0大于等于正数的矛盾。位置约束还对A、B排除环，并提供两两先后关系。两两先后只约束前件完成后才能加工后件；换模时间仍只对真正相邻的弧计入，不对所有先后工件重复计费。

## 4. 工位6与后段排序

每条B相邻弧i→j还要求 `C[j,6] >= C[i,6]`。整条B链因此按实际C6非降序排列；同时完成时允许选任一全序。强化约束对B的任意一对先后工件也施加相同要求。

B虽然用变量表示，但受到实际C6的排序约束，不能任意重排严格先完成、后完成的工件。不加入正epsilon强制不同完工时间；同一B排列在工位7～10一致使用。

## 5. 可行上界和 Big-M

`warm_start`只用于构造一个完整可行解和初始上界H，验证后才用于模型。原题最优值不大于H，因此搜索 `Cmax <= H` 不损失最优解。没有固定任何前段排列、工位6机器归属或后段排列。

记 `pmin[j,k]`为工件在工位k的最短加工时长，工位6取6-1时长，其余直接使用表2。定义：

```text
LS[j,k] = sum(pmin[j,t], t < k)
LC[j,k] = LS[j,k] + pmin[j,k]
UC[j,k] = H - sum(pmin[j,t], t > k)
US[j,k] = UC[j,k] - pmin[j,k]
```

开始时间下界为LS，完成时间上下界为LC、UC，开始时间上界为US。这些界只利用工件自身必须完成的加工时间，忽略等待和换模，因此对一般模型有效。

对于相邻机器约束取 `M=max(0,UC[i,k]+setup[i,j]-LS[j,k])`；到达后的换模约束取 `M=max(0,UC[j,k-1]+setup[i,j]-LS[j,k])`；工位6排序约束取 `M=max(0,UC[i,6]-LC[j,6])`。当对应弧未选中时，这些M保证约束不再限制时间变量。强化的两两加工先后约束采用相同推导，但不加换模时间。不存在任意极大常数。

## 6. 初始解的生成与范围

初始解使用编码 `(A, B, machines)`：A为前段排列，B为希望实现的工位6完工全序，machines按工件编号存机器归属。B在各机器上过滤后形成队列。按B逐件计算工位6时：

```text
earliest_finish = max(machine_previous_finish, arrival) + setup + duration
C[j,6] = max(earliest_finish, previous_finish_in_B)
S[j,6] = C[j,6] - duration
```

各队列首件setup为0。这个递推允许继续等待来实现B；B因此也确实是实际完工全序，包含一致的并列排序。前段、后段按最早下界递推。两个排列各遍历一次，解码为O(10n)，不需要排序C6。

对固定A、B、machines，原题任何满足这些选择的时间表都满足同一组下界。按A计算前段，按B计算工位6和后段时，每项递推均只对已经计算的前驱取最大值；由归纳可知递推结果不晚于任一这样的时间表。因此该编码覆盖至少一个全局最优解。这里用于初始解和小实例穷举；主精确模型仍直接保留一般时间变量。

## 7. 运行和验证

入口：`python -B -m problem2.exact_case1`。Gurobi生成同一数学模型的MPS，再由COPT读取复核；COPT使用Gurobi可行解作MIP start，不固定变量。日志、解、MPS、输入哈希、状态、界和完整CSV/JSON均保留；SVG甘特图中灰色为换模，颜色为工件。

`exact_validation.py`独立检查70道工序、加工时长、机器归属、相邻换模、到达时间、机器冲突、前后段排列、工位6实际完工顺序、时间原点和最终目标。允许继续等待，不调用解码函数。

`tests_exact_case1.py`覆盖6-2取整、等待导致完工并列、两台机器分别首件免换模、提前换模的错误记录，以及3工件全体288个编码。`--integration`另将该小实例的穷举最优值与Gurobi模型证明的最优值对照。

时间递推现统一放入`encoding.py`，原精确入口的调用格式保留。`build_model`新增可选`free_jobs`参数：默认`None`仍构建上述完整模型；显式提供工件集合时，固定其余工件的A、B相对顺序和机器归属，不固定位置或工序时间。该模式属于受限模型，其OPTIMAL和下界不代表原题全局结论，详见 [遗传与受限精确求解V1](遗传与受限精确求解V1.md)。原全局最优证据不修改，新的模型MPS另存于新结果目录。

最优性结论须同时满足求解器OPTIMAL状态、上下界一致和独立验证通过。浮点求解器的证据按其数值容差理解；CSV保留原始浮点时间，不以手动取整替代验证。
