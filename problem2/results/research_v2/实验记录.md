# 启发式与区间精确重排研究记录

日期：2026-10-10。已完成原因分析、模型强化、区间重排实现及逐次对照。新方法在本轮三个Case 2种子中，均以不多于重复退火的追加用时得到更好的解；这支持采用该方案，但不是对所有实例、种子和求解器参数的保证。Case 2尚无最优性证明。

## 1. 为什么第一版效果不好

### 固定范围排除了更好的解

Case 1退火与变邻域的三个受限范围均已证明最优5063，但完整模型的已知全局最优是5031。问题不是给求解器的初始解无效，而是这些附加固定约束已经排除了所有5031解。

两种方法到第三轮都仍固定“后段J4在J2前面”，与已保存的一份5031方案冲突。退火第三轮还有另外两条与该方案冲突的直接先后关系。这里只用已知最优调度作事后诊断，不能断言该单独关系排除了全部最优调度，更不能把最优排列输入新的选择算法。

### 按记录数量解除不等于放开决策

第一版退火的41条直接记录中，21条单独删除不会改变推导出的机器、先后和相邻决策；变邻域35条中有18条。原因是其他关系仍能推出被删关系。按25%的条数删除，再用字典顺序处理同分关系，既可能删掉重复记录，也可能长期保留需要改变的后段关系。

新的区间方案不继续按条数解除：每轮从当前最好解重新选择允许变化的位置，并重新生成限制。这允许暂时固定某些关系，但不会把一次搜索的后期一致永久当作必须保持的顺序。

### 模型仍大，时间界仍松

Case 2第一版有3732个0/1变量，120秒只处理根节点。此次删除更多不可能的弧、加强时间界后降为2601个，但仍用满120秒且没有改善，范围下界仅6294.698，上界11086，gap为43.22%。

这说明单纯继续减少部分变量仍不够。大量弧和先后变量尚未确定时，线性松弛允许它们取分数，Big-M约束不能完整表达整数调度中的机器不重叠，求解器要花很多时间加强下界。稳定关系模型没有推导出额外的必选相邻弧，工序时间界也仍宽。

## 2. 新方案及模型变化

采用“贪心及完整局部下降 → 一次模拟退火 → Gurobi区间重排”。每轮在前段A、后段B各选一个连续区间，区间内重排，相关工件允许换工位6机器；区间外位置与其他机器归属暂时保留。通过关键工序、样本分歧和随机选择轮换区间，不遍历所有工件组合。

强化模型删除被固定顺序排除的紧邻弧，并利用唯一前驱或后继推导必选弧。确定相邻时才加入该换模时间，由加工、转移和已固定关系向前、向后推导时间界，进而收紧Big-M。全部工件的10工位时间仍保留，工位6继续等待与实际完工排序仍由一般模型处理。

本轮Case 2区间模型通常只有约200个0/1变量。变量数少且固定的相邻关系多，时间界也能利用更多已确定的加工和换模条件，多数范围可以很快求到最优。该最优性仅针对本轮区间范围。

设计、公式、参数及范围说明见 [V2设计](../../docs/区间精确重排与模型强化V2.md)。旧稳定关系入口、遗传入口及历史结果保留，不覆盖原始输入，没有新增依赖。

## 3. Case 1诊断

从旧退火的5063参考编码开始，原固定关系加模型强化仍为5063；新区间方案第9轮降到5031，该轮求解器Runtime约2.376秒，首次达到5031前后的全部搜索都未读取最优基准。13轮区间阶段总耗时23.683秒，完成既定覆盖规则后结束。

这是复用已有调度的诊断，不包含原初始化和退火时间。第一轮宽度5，连续失败后增到6；第9轮成功说明更换和扩大实际允许变化的区间能解除第一版一直保持的限制。

另做三个独立退火种子：11得到5063，23得到5054，37得到5031。三个搜索中70个不同较好样本与参考最好解的交集选出34条关系，受限模型很快证明5031，但该结果已经在启发式阶段产生。它不能作为“多种子一致关系帮助找到5031”的证据，也不能忽略三次初始化和搜索成本。

证据：[5063出发的诊断](case1_probe01/summary.json)、[多种子结果](case1_multiseed01/summary.json)。Case 1全局证明仍来自以前的完整模型；本轮受限求解未新增全局证明。

## 4. Case 2：同一参考解的模型对照

三条路线依次读取同一份11086完整调度，均获得完整MIP start。Gurobi 13.0.2，8线程，精确阶段时间上限120秒；区间方案另设每轮5秒、最多36轮，先到者停止。以下实际用时包含该阶段建模与导出，不包含已存在参考调度的生成成本。

| 路线 | 最终Cmax（秒） | 精确阶段实际用时（秒） | 0/1变量数 | 结果 |
| --- | ---: | ---: | ---: | --- |
| 强化后的原稳定范围 | 11086 | 120.718 | 2601 | TIME_LIMIT，没有改善 |
| 区间重排 | 10978 | 68.176 | 随区间变化，通常约200 | 36轮，有多次改善 |
| 完整模型，同样提供11086初始解 | 11086 | 121.620 | 6302 | TIME_LIMIT，没有改善 |

完整模型的下界4251.420、gap为61.65%，只处理根节点。稳定模型的下界6294.698只对固定范围有效，不能拿它充当完整模型的更强全局下界。

本次Case 1多种子诊断与Case 2稳定阶段曾同时运行，因此稳定阶段用时不适合精细比较。区间阶段和完整模型阶段在Case 1诊断结束后依次进行。结论限于这次默认求解参数、同参考解的诊断；不是完整模型无MIP start的冷启动比较，也没有测试所有求解器调参方案。

10978为本次研究中已经核查的最好Case 2可行值，不是最优值。证据：[汇总](case2_probe01/summary.json)、[完整模型结果](case2_probe01/full/result.json)、[10978调度](case2_probe01/window/final/result.json)、[CSV](case2_probe01/window/final/schedule.csv)、[甘特图](case2_probe01/window/final/gantt.svg)。

## 5. Case 2：逐种子与追加退火对照

种子11、23、37各自重新运行完整初始化和第一次退火，再从同一份该种子的最好解分成两条路线：一条用区间精确阶段，另一条只重复模拟退火。

重复退火只从自己的最好解继续，不使用精确阶段得到的新解。每次完整运行既有降温规则，直到其追加用时至少达到区间阶段实际用时；最后一次允许多用时间。所有试验串行进行，没有使用5031或其他已知答案停止，以下按逐次结果报告，不用平均值。

共同准备成本包括初始化、第一次记录退火和对应结果导出。表中分别给两条方案计入该成本；它们共享同一次准备，不是分别重新执行。入口最前面的Excel读取、源码快照等少量开销不计入此阶段合计。实际带 `--sa-comparison` 的诊断命令会执行两条路线，命令墙钟时间大于任何单条路线。

三次中，区间阶段均在更少或近似的追加时间下得到更好的解，改善不是仅与一次退火比较额外求解时间得出的。但只验证了三个种子，时间不是严格一致，Gurobi的并行搜索和机器状态也会影响结果，不能宣称普遍优于退火。

本次区间改善仍有限，三个完整流程最好10979。复用旧参考调度的诊断得到10978，其区间选择没有使用样本分歧，说明尚不能断言记录分歧一定改善区间选择。多种子搜索也增加成本，因此新入口默认只运行一个种子，多种子交集保留为研究选项。

逐次证据：[种子11](case2_seed11_run01/summary.json)、[种子23](case2_seed23_run01/summary.json)、[种子37](case2_seed37_run01/summary.json)。

## 6. 验证、运行与建议

35项相关单元测试通过。新增6种强化模型与3工件全部288个编码穷举对照通过；保留的完整、遗传局部及V1稳定模型共6项对照也通过，合计12项模型核验。它们验证实现及小实例最优值，不代替Case 2全局证明。

六个研究目录共372份完整调度和对应CSV、SVG，以及171个模型通过独立核查；输入哈希及各轮模型哈希、准确源码快照也核验。记录见 [verification.json](verification.json)。可重复运行：

```powershell
python -B -m problem2.audit_research --output problem2/results/research_v2
```

推荐从一个种子开始，不默认使用三次启发式，也不默认求完整Case 2模型：

```powershell
python -B -m problem2.research_main --case 2 --seeds 11 --variants window --solver-seconds 120 --round-seconds 5 --max-rounds 36 --output problem2/results/research_v2/case2_new
```

需要对照追加计算效果时加 `--sa-comparison`，会显著增加诊断命令用时。输出目录已存在时拒绝覆盖。源文件修改前备份见 [.backups/20261010-research-v2](../../../.backups/20261010-research-v2/manifest.json)，第一轮Case 1诊断也保存了其准确源码版本。当前试跑与求解任务均已结束。

本轮建议采用区间精确重排作为主方案，稳定关系用来提供选择参考，不把其一次搜索的一致结果全部永久冻结。接下来若扩大实验，应优先验证区间选择、跨较远位置的移动和模型预算分配；是否值得增加更多启发式运行，仍须把新增成本一起比较。现有证据支持本次改进，不支持原题全局最优或无限延长预算后的算法优劣结论。
